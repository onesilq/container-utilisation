FCL button and container animation

The two new pieces of the shipment's Overview card. The FCL button sits in the card's header and shows how full the container is; clicking it opens the utilisation popover, where the 3D container loads. Each is one small file with no libraries, and neither needs anything else from the prototype.

The button in the shipment's Overview header: the mode, a small container, and the percentage used. That's the higher of space and weight used, and the fill follows it too. One small file works it out from the cargo's volume and weight and draws it. Clicking it opens the utilisation popover, whose container is in the Container animation tab.

States

Rules

WhatRule
Space usedCargo CBM ÷ (containers × capacity). Capacity is the container's nominal inside volume: 33 CBM for a 20' GP, 67 for a 40' GP, 76 for a 40' HQ.
Weight usedCargo kg ÷ (containers × max payload): 28,200 kg for a 20' GP, 26,700 for a 40' GP, 26,500 for a 40' HQ.
PercentageThe higher of space used and weight used, rounded, since a container is full when either runs out. With 40% space and 60% weight it reads 60%. Anything above 0 and under 1% reads “<1%”. Not capped, so an overfilled container can read above 100%.
Fill length17.2 × the percentage shown ÷ 100, in the container's 26 × 14 units, starting at x 2.3. It stops at 100%, at the door line.
Fill colourAlways #7681FC, the Analytics page's volume colour, at any percentage and also when weight is the higher figure. It doesn't change with how full the container is. In the popover the Volume bar uses the same colour and the Weight bar uses #F9B474, the Analytics weight colour.
Weight-limitedWeight at 90% of max payload or more: a “Weight-limited” chip follows the button.
Not known yetNo cargo volume yet: an empty container and a grey “—”. The tooltip says “Space used not known yet”.
TooltipOn hover or keyboard focus, under the button with the right edges lined up. One line, in regular weight like the carbon tooltip beside it: “49% of space used”. When weight is higher it names weight instead: “60% of weight limit used”. Hidden while the popover is open.
Screen readersThe button reads “FCL, 49% of container space used”, “FCL, 60% of weight limit used”, or “FCL, space used not known yet”. The container drawing is hidden from them.
ClickOpens the utilisation popover (see Container animation), whose big figure is the same percentage. Set aria-expanded="true" on the button while it's open; that gives it the white shape and hides the tooltip. The white is made for the lavender Overview header (#EBEDFF), so it won't show on a white background.

Use it

<!-- or import it with your bundler -->
<script src="fcl-unit.js"></script>

el.innerHTML = FclUnit.button({
  mode: 'FCL', type: '40HQ',
  containers: 1, cbm: 37, kg: 1000            // cbm or kg can be null until known
});

el.querySelector('[data-fcl]').addEventListener('click', e => {
  e.currentTarget.setAttribute('aria-expanded', 'true');  // and open your popover
});
button(shipment)
The whole button as an HTML string: “FCL”, the container, the percentage and the tooltip, with the “Weight-limited” chip after it when the cargo is heavy. Put it in a flex row; the product's header row has an 8px gap.
glyph(space, weight)
Just the 26 × 14 container as an SVG string. Both are percentages from 0 to 100, and the fill follows the higher; pass null for space when it isn't known. Use it wherever the container shows on its own.
measure(shipment)
The numbers behind it: space and weight used and the rounded text for each, which one is higher and the figure shown (used, usedText, byWeight), the capacities, and whether it's weight-limited. Use it if you draw the button in your own components.
capacity, thresholds, colors, css
The capacity table (add your other container types to it), the 90% weight-limited line, the colours and the styles. The styles are added to the page the first time it draws.
  • The button takes the page's font. The product uses Inter: 14px semibold, #111, with figures that line up (tabular-nums).
  • In React or Vue, render the string with dangerouslySetInnerHTML or v-html, or rebuild the markup in your own component from measure() and glyph(). The class names all start with fcl-.
  • The product has one container per shipment, so containers is 1. The sum already allows for more.

The 3D container in the utilisation popover that the FCL button opens. One small file draws it as SVG at any fill level, slides the cartons in, then swings the doors shut.

Reduced motion is on for this device, so it shows the finished picture without animating. The product does the same.

Timeline

PartWhenHow
Container0 – 250 msFades in, ease-out.
Each carton250 ms + its place × stagger420 ms, cubic-bezier(.2, .75, .25, 1). Slides in from the door end (its distance to the doors, up to 3.2 m, plus 0.8 m) and drops 0.3 m into place, fading in over the first 35%.
Staggermin(55, 1,000 ÷ cartons) msWhichever is shorter, so every carton has started within about a second, however full the container is.
Loading orderFrom the end wall toward the doors, a slice at a time. In each slice, bottom to top, back row first.
Doorsmax(900, 250 + cartons × stagger + 420) + 100 msOpen at 105° while the cargo goes in, then swing shut over 700 ms, ease-in-out, in 24 steps. The 900 ms minimum lets the popover's meter bars (0.9 s) finish first.
After thatNothing keeps running. It's a still SVG.

Use it

<!-- or import it with your bundler -->
<script src="container-animation.js"></script>

const c = ContainerAnimation.draw(0.22, { width: 288 });  // fill from 0 to 1
el.innerHTML = c.svg;
ContainerAnimation.play(el);                              // plays once; call again to replay
draw(fill, { width, height })
Returns the SVG as a string, with its width and height, the number of cartons (fill × 60, rounded) and the timing for that fill. The popover uses width 288; the Overview note uses 132.
play(element)
Plays the animation once on the SVG inside the element. Call it again to replay. It does nothing, and returns false, when reduced motion is on or the tab is hidden.
  • Without play(), the SVG is the finished picture: cartons in, doors shut. The Overview note uses it that way, still.
  • Every container type uses this one shape. Show the type, like “20' GP”, in text under the drawing.
  • The SVG is hidden from screen readers. Put the % used in text beside it, as the prototype does: the higher of volume and weight, labelled “Volume used” or “Weight used”.
  • In React or Vue, render the string with dangerouslySetInnerHTML or v-html, then call play() on the mounted element. The styles it needs are added to the page the first time it draws, and are also exported as ContainerAnimation.css.
